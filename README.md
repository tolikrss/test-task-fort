# Моніторинг полів

Веб-застосунок для керування сільськогосподарськими полями: поля на карті, моніторингові точки в межах поля, панель з фільтрацією, пошуком і сортуванням. Без бекенду: поля — mock GeoJSON, точки зберігаються в localStorage.

## Запуск

Потрібен Node.js `^22.12.0`, `^24` або `>=26` (вимога Vitest 5).

```bash
npm install
npm run dev        # http://localhost:5173
```

## Можливості

- 5 полів довільної форми на карті; вибір кліком на карті або в списку, активне поле виділене, карта летить до нього; назва, культура й площа.
- Режим редагування закліком «+ Додати точку»: клік у межах будь-якого поля → форма (тип, опис); якщо поле не активне, воно стає активним. Клік поза полями — повідомлення. Координати WGS 84 і MGRS (обчислюється на фронтенді).
- Маркери з кольором та іконкою за типом, легенда, popup з деталями, видалення з підтвердженням.
- Панель: фільтр за типом, пошук за описом, сортування за датою. За замовчуванням у списку всі додані точки з назвою поля; перемикач «Лише активне поле» звужує список. Список і карта синхронізовані: клік у списку → переліт до маркера; клік на маркер → підсвічування рядка.
- Desktop: бічна панель. Tablet (до 1024px): drawer поверх карти.
- Клавіатура: Esc скасовує додавання / закриває панель чи діалог; видимий фокус; модальні елементи тримають фокус.

## Стек

React 19 · TypeScript · Vite 8 · Leaflet + react-leaflet 5 · Zustand 5 · React Hook Form + zod 4 · Tailwind CSS v4 · Turf · mgrs · Vitest · Oxlint · ESLint · Prettier

## Структура

```
src/
  app/        # розмітка, drawer, ErrorBoundary, глобальний Esc
  features/
    fields/   # GeoJSON полів, zod-модель, store активного поля, список і картка поля
    points/   # модель точки, store з persist, UI-стан, форма, фільтри, список
    map/      # карта: шари полів і точок, клік-обробник, контроли, іконки
  shared/     # lib (geo, format, storage), hooks, ui (Button, ConfirmDialog, toast)
```

Фічі імпортують одна одну лише через `index.ts`; залежності однонапрямлені: `map → points → fields → shared`. Цикли заборонені лінтером.

## Архітектурні рішення

**Zustand, кілька невеликих store.** `useFieldsStore` (активне поле), `usePointsStore` (дані точок + persist), `usePointsUiStore` (режим додавання, чернетка, фільтри, фокус, підтвердження на видалення). Альтернативи: Redux Toolkit — більше шаблонного коду для трьох сутностей, надто ускладнює код для описаної задачі.

**Похідні дані — чисті функції.** `selectVisiblePoints(points, filters, activeFieldId)` не залежить від React і store, тож покрита unit-тестами; карта й список беруть результат з одного хука `useVisiblePoints`, тому завжди показують один і той самий набір.

**Поля — дані, а не стан.** GeoJSON імпортується як рядок і парситься zod-схемою, під час першого рендеру: можливі помилки в даних перехоплює ErrorBoundary. Store зберігає лише `activeFieldId`; «перше поле за замовчуванням» — у `useActiveField`, тож store не залежить від даних.

**Валідація.** zod перевіряє все, що приходить ззовні: GeoJSON полів, дані з localStorage (по кожному запису: запис з помилками не впливає на інші), форму. Тобто всередині застосунку типи вже гарантовані.

**MGRS не зберігається.** Він обчислюється з lat/lng під час показу, тож не можлива ситуація розходження з координатами. Turf і mgrs обгорнуті в `shared/lib/geo.ts`: решта коду працює з `{ lat, lng }`.

**Явний режим додавання точки.** Без цього випадковий клік - і точки могли б створюватися помилково. Режим робить дію передбачуваною - чернетку можна переставити повторним кліком, Esc скасовує.

**Нативний `<dialog>`** для підтвердження: пастку фокусу, інертний фон і Esc дає браузер.

**Drawer — оверлей.** На планшеті панель накриває карту, а не зсуває її, тож Leaflet не треба повідомляти про зміну розміру (`invalidateSize`).

## Обробка помилок

| Ситуація                                  | Поведінка                                         |
| ----------------------------------------- | ------------------------------------------------- |
| Некоректний GeoJSON полів                 | ErrorBoundary: екран помилки з деталями валідації |
| Пошкоджені / частково невалідні точки     | Валідні відновлюються, решта пропускається, тост  |
| localStorage недоступний або переповнений | Робота в пам'яті, один тост «не вдалося зберегти» |
| Тайли карти не завантажуються             | Один тост за сесію; поля й точки працюють         |
| Клік поза всіма полями                    | Тост, точка не створюється                        |
| MGRS не визначений (поза 80°S–84°N)       | Показуємо «—»                                     |
| Невалідна форма                           | Повідомлення під полем                            |

## Тестування

Vitest покриває частину "чистої" логіки: геометрію (точка на межі поля, у виїмці угнутого поля), MGRS, форматування, zod-схеми, фільтрацію/пошук/сортування, store точок з моделюванням з пошкодженого localStorage. Компоненти й карту перевірено мануальним тестуванням (сценарії — у розділі «Можливості»).

## Як реалізовані неоднозначні моменти

- Карта показує ті самі точки, що й список (з урахуванням фільтрів).
